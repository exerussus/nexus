# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [0.2.5]

### Изменено
- Плагин `app` 2.5, вкладка «Консоль»: убрана карточка «Выбор цели» — с app-core 4.2 AppDeck не выбирает
  цель сам (механизм выбора — у проекта), настроек выбора больше нет.

## [0.2.4]

### Добавлено
- Плагин `app` 2.4: вкладка «Консоль» — настройки AppDeck (app-core 4.1+): режим запуска, клавиша, окно
  (размер, высота шторки, порядок отрисовки, курсор, панель и стили), ёмкость логов и свёртка повторов,
  история, выбор цели (пикер, дальность, слои), метрики и мини-HUD. Статус: где AppDeck включится
  (редактор / development / релиз) и лежит ли ассет в Preloaded Assets (с кнопкой «Добавить»); создание
  ассета через AppCore; сброс сохранённого у игрока (окно, история, фильтры, закрепления).
  На сборку `Exerussus.AppCore.Deck` страница не ссылается — с app-core 4.0 вкладка просто сообщает, что AppDeck нет.

## [0.2.3]

### Изменено
- Плагин `app` 2.3, «Заливка в S3»: путь в бакете разделён на «Главную папку» (по желанию, по умолчанию
  выключена) и «Папку версии» (`v{version}`) — версии можно класть прямо в корень бакета. Старое поле
  «Папка в бакете» переносится автоматически: `{product}/v{version}` → главная папка `{product}` + `v{version}`.

## [0.2.2]

### Добавлено
- Плагин `app` 2.2: пост-шаг «Заливка в S3 (rclone)» — папка сборки и/или zip в бакет. Общие настройки
  (endpoint, регион, бакет, папка в бакете по шаблону, sync/copy, исключения) — в `build-config.json`;
  ключи — личные (`UserSettings/…/app/s3-credentials.json`) или из переменных окружения, rclone получает
  их через окружение. Кнопка «Проверить подключение». Снятие маркеров папок Selectel перед sync.
  Заливка в корень бакета и папки с `..` запрещены.
- Шаг «Zip»: шаблон имени архива с токенами `{product} {version} {hash} {profile} {platform} {date}`
  (по умолчанию `{product}_{version}_{hash}` — как раньше) и предпросмотр.

### Исправлено
- История сборок: размер архива брался из первого артефакта (например, `version.json`), теперь — из `.zip`.

### Изменено
- Контракт шага сборки: `BuildSettingsUI(settings, changed, AppKit kit)` вместо `IPageUi` — шагу доступен
  контекст страницы (личные файлы, статус); `BuildStepContext.UserConfigPath(file)` — личные файлы при сборке.

## [0.2.1]

### Добавлено
- Журнал сообщений (`NexusStatusLog`, ядро): всё, что страницы пишут в `Context.SetStatus`, копится
  (до 50 сообщений, в пределах сессии редактора, одинаковые подряд схлопываются) с источником и временем.
- Окно сообщений (`NexusStatusWindow`): список слева, полный текст справа в поле только для чтения —
  выделение, копирование, «Копировать всё», «Очистить».
- Кнопка «Сообщения» рядом с Refresh — открывает окно на последнем сообщении; красная, пока есть
  непрочитанная ошибка. Падение страницы попадает в журнал со стеком.

### Изменено
- Строка статуса — одна строка с многоточием; клик или «подробнее ›» открывает окно сообщений.
  Соглашение: первая строка статуса — коротко, остальное — подробности.
- Плагин `workspace` 1.2: сцена в рабочей области больше не сыплет «Do not use ReadObjectThreaded on
  scene objects» — главный ассет резолвится без перебора объектов файла, для сцен перебор не делается.

## [0.2.0]

### Добавлено
- Корни плагинов по маркеру `nexus-plugins.json`: папка с маркером в Assets или в любом пакете
  становится корнем плагинов. Поиск — только кнопкой «Найти корни плагинов» в Manage; найденное
  хранится в `ProjectSettings/Nexus.json` (`discoveredRoots`, asset-пути, коммитится).
- Manage: секция «Корни плагинов» — встроенный, ручные и найденные корни, пропавшие и дубли.
- `NexusPaths.AssetToAbsolute`; `ToAssetPath` понимает пакеты из кэша (иконки плагинов из git-пакетов).
- `CHANGELOG.md`, README движка.

### Удалено
- Плагин `resources-auditor`. Если он был развёрнут, в Manage он станет «осиротевшим» — удалите его там кнопкой Clean.

### Изменено
- Nexus устанавливается как UPM-пакет: зависимость `com.unity.nuget.newtonsoft-json` объявлена
  в `package.json` (раньше Newtonsoft должен был быть в проекте сам). Если в проекте лежит
  Newtonsoft.Json.dll (NuGet и т.п.) — удалите его, иначе будет две сборки с одним именем.
- App 2.1: вариант «Текущий профиль» на вкладке Сборка собирает по активному Build Profile (сцены
  из его переопределения) и больше не переключает профиль на голую платформу.
- Workspace 1.1: из asmdef убрана ссылка на несуществующий asmdef `Newtonsoft.Json`
  (dll подхватывается авто-ссылкой).
