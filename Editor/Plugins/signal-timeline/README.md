# Signals

Swimlane-визуализация сигналов из `SignalRegistry`: одна дорожка на сигнал,
время идёт по горизонтали, маркеры окрашены по типу события. Клик по маркеру
открывает строку исходника, породившую событие.

## Режимы

- **Timeline** — дорожки по сигналам, пилюли-маркеры по времени.
- **List** — плоский список событий с фильтром по сигналам и колонками.
- **Graph** — лес деревьев вызовов по причинно-следственным связям Invoke.

## Тип страницы

**Constitutive**: в развёртку плагина входит и сам рекордер
(`SignalRegistry`, `[InitializeOnLoad]`) вместе со страницей, попапом,
конфигом и стилями. Значит:

- **Включён** → рекордер материализуется, `[InitializeOnLoad]` ставит хуки
  `Signal.EditorHook.*`, запись идёт, страница показывает данные.
- **Выключен** → все файлы вытесняются, рекордера в проекте нет: запись
  прекращается, оверхед хуков исчезает («off значит off»).

Если нужна запись НЕЗАВИСИМО от страницы (servicing) — рекордер надо, наоборот,
вынести из плагина в стабильную editor-сборку.

## Внешняя зависимость

Единственная — рантайм-сборка `exerussus.signals`, откуда резолвятся
`Signal` / `Signal.EditorHook` / `ISignal` / `SignalEventKind` и модель
(`TimelineEvent` / `SignalTrackData` / `SignalTimelineModel`). Она существует
всегда, т.к. на неё ссылается игровой код.

## Внимание: SignalsConfig — это ассет

`SignalsConfig` — ScriptableObject с ассетом на диске. Скрипт едет в развёртке,
поэтому при выключении плагина ассет `SignalsConfig.asset` временно теряет
привязку к типу (при повторной развёртке .meta-GUID скрипта меняется). Если
настройки должны переживать циклы вкл/выкл без потери привязки — держи
`SignalsConfig` в стабильной editor-сборке вне развёртки, либо переведи его
хранение на `Context.GetUserConfigPath(...)` (JSON).
