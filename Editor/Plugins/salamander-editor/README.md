# Salamander

Страница-оболочка над IDE Salamander из пакета (`Dsl.Ide`). Та же IDE
работает в игре (`SalamanderIdeWindow`) — здесь только редакторский хост.

## Что умеет

- **Модули целиком.** Дерево модулей и файлов (панель «Файлы»), вкладки,
  компиляция всего воркспейса с несохранёнными правками — ссылки между
  файлами и модулями не дают ложных ошибок.
- **Подсказки** — общий языковой сервис `Dsl.Tooling` (тот же, что в VS Code
  и Rider): автодополнение (`Ctrl+Space`, после точки, `event `, `new `),
  подсказка параметров (`Ctrl+Shift+Space`), hover, переход к определению
  (`F12`, `Ctrl+клик`), структура файла.
- **Редактор**: номера строк, текущая строка, парные скобки, поиск и замена
  (`Ctrl+F` / `Ctrl+H`, `F3`), переход к строке (`Ctrl+G`), комментарий
  (`Ctrl+/`), сдвиг блока (`Tab` / `Shift+Tab`), дублировать строку (`Ctrl+D`),
  удалить строку (`Ctrl+Shift+K`), перенос строк (`Alt+↑/↓`).
- **Ничего не теряется**: несохранённые правки и вкладки переживают
  перекомпиляцию C#, вход в Play и перезапуск редактора. Файл, изменённый на
  диске, перечитывается сам; при несохранённых правках — баннер конфликта.
- **Play Mode**: кнопка «Применить в игре» перезагружает скрипты работающего
  `ScriptHostBootstrap`, логи скриптов — во вкладке «Консоль».

## Настройка

- **Папка модулей…** — где искать модули (по умолчанию `StreamingAssets`,
  если там есть модули, иначе `Assets`).
- **API-манифест…** — `salamander-api.json` игры (по умолчанию ищется рядом
  с модулями). Его можно и перетащить на страницу.

Требуется пакет Salamander со сборками `Dsl.Core`, `Dsl.Tooling`,
`Dsl.Unity`, `Dsl.Ide`.
