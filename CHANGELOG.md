## [2.0.0-pre.1]

Этап 1 Nexus 2.0: Nexus Daemon.

### Добавлено
- **Nexus Daemon** (`nexusd`, `Tools~/daemon/nexusd.dll`, .NET 8+ с roll-forward; исходники — `Daemon~/`). Один на
  машину, запускается редактором с включённым CLI, переживает перезагрузки домена и закрытие Unity:
  - реестр проектов по файлам экземпляров, вызовы с ожиданием редактора и заданий, повтор при «занят»;
  - HTTP API v1 на `127.0.0.1:47800–47809` с токеном (`tokens.json`), без запросов из браузера: `/v1/projects`,
    `/v1/calls`, `/v1/projects/<id>/commands`, `/v1/projects/<id>/artifacts/…`, `/v1/daemon`;
  - файловый адаптер `NexusTemp/cli` (формат 1.0): вызов принимается сразу, даже во время перезагрузки домена;
  - сторож и будильник внутри демона (пульс — `ping` главного потока раз в 2 с).
- Команды `bridge.hello`, `daemon.status`; `ping` отдаёт фазу редактора.
- Клиент `nexus` 5 — через API демона; `nexus result <id>`; код 13 — демон не запущен.

### Изменено
- Прямой TCP к редактору мимо демона выключен (`nexus-cli.json` → `DirectTcp` для отладки).
- Закрытие редактора оставляет файл экземпляра в состоянии `closed` (CLI включён — демон знает проект).
- Файл экземпляра: `daemonProtocol`, путь к `Editor.log`.
- `nexus-fs` 5: с демоном не ждёт перезагрузку сам, диагноз показывает демон и редактор.

### Удалено
- Файловый канал внутри Unity (`NexusCliFileChannel`) и сторож на PowerShell (`nexus-watchdog.ps1`) — их ведёт демон.

## [1.0.0]

### Добавлено
- Файловый канал CLI: `<проект>/NexusTemp/cli` (`requests → active → done`, `tasks/…`, `alive.json` — пульс раз в
  2 с). Для агентов и сред без доступа к localhost. `NexusTemp/.gitignore` создаётся сам.
- Клиент `nexus-fs` (python3, без зависимостей): ставится в `NexusTemp/nexus-fs`, переводит пути Windows в пути
  своей машины, ждёт перезагрузки домена, коды 10/11/12 — нет канала, нет ответа, редактор не отвечает.
- Задачи: шаги-команды по очереди, `onError` stop/continue, `always`, `expect` (exit/output/notOutput/data),
  подстановки `${шаг.поле}` и `${args.ключ}`, отчёт по задаче и шагам, артефакты.
  - Сценарии — `ProjectSettings/Nexus/tasks/<имя>.json`.
  - Команды `task.run` (`--steps "…"`, `--set`, `--list`), `task.status`, `task.cancel`, `tasks`, `wait`
    (`--seconds`, `--frames`, `--idle`).
  - Пока идёт задача, сторонние команды, меняющие состояние, отклоняются (`--force` — выполнить всё равно,
    `"lock": false` в сценарии — без блокировки).
- `NexusCommandAttribute.ReadOnly` — команда только читает и проходит блокировку задачи.
- `NexusCommandContext.Force`, `NexusCommandContext.Task`.
- `NexusCommandContext.RetryLater(причина, срок)` — «ещё не готово»: ядро повторяет команду заданием `retry`, пока
  она не выполнится; вызывающий ждёт один итог.
- Срок и хранение задаёт вызывающий: `timeout`, `keep` у запроса и задачи.
- Сторож CLI (Windows): процесс `nexus-watchdog.ps1` рядом с редактором; главный поток стоит — `stall.json` с
  фазой, окнами процесса (модальное окно видно по заголовку) и ошибками из `Editor.log`. Метки домена
  `domain.json`, `startup-error.txt`. `nexus-fs` печатает диагноз сам, `nexus-fs diag` — полный.
- Будильник сторожа: Unity, застрявшая в фоне после перезагрузки домена, будится без мыши — `soft` (по умолчанию)
  или `focus` (передний план на пару секунд с возвратом фокуса); `cli.wake`, список в Manage, журнал `wake.json`.
- Плагин `app` 3.9.0: `app.open page|popup <id>`, `app.open --close` (в Play).

### Изменено
- Скриншоты и отчёты тестов — в `NexusTemp/screenshots` и `NexusTemp/tests`.
- Клиенты 4: `--force`, срок отправляется только если задан.
- CLI выключен — файловый канал не пишет файлов, `NexusTemp/cli` удаляется.

## [0.3.1]

### Добавлено
- Плагин `app` 3.1, «Сборка → Пайплайн»: пост-шаг «Заливка в PlayFlow» (`playflow-upload`). Заливает серверную
  сборку в PlayFlow Cloud через Public API v3: zip шага Zip (или свой архив папки сборки), executable_path
  находится в архиве сам, ожидание обработки (при ошибке — хвост логов обработки), по желанию перезапуск
  сервера по instance id на новую версию и вывод нового адреса в лог. Серверный ключ — личный
  (UserSettings `playflow-credentials.json`) или переменная окружения; без ключа шаг пропускается.
  Важно: при перезапуске PlayFlow выделяет новые host и порт — клиент должен узнавать адрес по instance id.
